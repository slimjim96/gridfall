# Terrain Tiles + Editor Overlay — v1

**Slug:** `terrain-tiles` · **Status:** done · **Verified at trace:** unchanged

Closes the `tile-art-pipeline` follow-up named in [map-themes-v1](map-themes-v1.md) — "ground images
rather than flat colours" — and rebuilds the board editor's overlay, which is where you select them.

## What Shipped

### A folder is a theme

`presentation/tiles/<theme>/<kind>/<name>.png`. Drop a folder in and it becomes selectable: no code
change, no registration, no Godot import step. Contract in
[`presentation/tiles/README.md`](../../presentation/tiles/README.md).

- **Connection-aware path tiles.** A file named by which edges the road leaves through — `ns` a
  straight, `es` a corner, `nesw` a crossroads, sixteen masks in all — so a painted corridor joins up
  as a road instead of tiling as squares.
- **Variants per kind.** `stone.png`, `stone-2.png`, `bush.png` are three ways a wall can look.
  Distribution is a **fixed hash of cell coordinates**, never an RNG: the board rebuilds on every
  brush stroke, and a random pick would reshuffle the whole map each time you painted one cell.
- **Everything optional.** Missing mask → unmasked variant → the theme's flat colour. A theme can be
  built one folder at a time, and the seven existing colour ramps keep working untouched.
- **`F7` reloads from disk** without relaunching. That is why tiles live outside `res://` at all.
- Side walls of raised cells are painted the tile's own **average colour**, computed at load, so a
  wall's sides match its top with no second image.

### The editor overlay, rebuilt

A left rail (status card, validation card, maze estimate), a bottom brush bar showing the five
brushes **as the tiles they paint**, and `F1` as a centred card.

Laid out by containers. The old version was five labels at hand-computed y offsets and the offsets
were wrong — the maze estimate drew straight through the last finding, because the guessed line
height was 18px and the real one was 26. Severity is now per row, so an error is red *and the info
line beside it is not*; the old single-label panel turned everything red at once, which made the
error harder to find rather than easier.

### Placeholder art you can throw away

`roadway` — 24 tiles, generated by `presentation/tiles/make-placeholder-tiles.py`, byte-identical on
every run because every speckle comes from a fixed LCG seeded from the tile's own name. It exists to
prove the pipeline and to be replaced.

## A tile changes how a cell looks and nothing else

`CellKind` still decides every rule. A tile is chosen *after* those decisions, and no code path
carries an image toward the simulation. The game capture hash was `b9c3bc7c95e6f726` before and after
the last render change, and `TheThemeIsNotSimulationState` still holds.

The theme was already an opaque string that Core carries and never reads, so **nothing new crosses
the boundary** — this slice only changed what the view does with a string it already had.

## The proof that mattered most

An un-tiled board renders **byte-identically** to the committed baseline — `md5
711cb6f427594330b4b4ea27f8e0bd3d` — after a terrain-mesh restructure that added UVs, split tops from
sides, and introduced per-texture surfaces. Where the change should be invisible, it provably is.

## A crash this slice found and fixed

Painting over the goal and then pressing `F4` threw `IndexOutOfRangeException` and killed the editor.

`RebuildGeometry` had always guarded a goal-less draft, because painting mid-stroke is obviously
allowed to be illegal. `RebuildEverything` had not — so the editor crashed at the exact moment it was
one line away from reporting "map has no goal". Pre-existing, reachable via `F4` and `Ctrl+N`; the new
`F7` would have added a third door.

> **Anything that rebuilds has to survive an illegal draft, not just the stroke handler.** Half the
> rebuild paths being safe is the shape of bug that looks fixed for a year.

Regression test pins the *precondition* — `PathSystem` cannot build without a goal — rather than the
symptom, so the guard can be deleted the day that stops being true.

## What the frames caught

Three defects invisible to the compiler and to all 176 tests:

- **Walls rendered untextured.** `occupied` used `PathSystem.IsBlocked`, true for blocked *terrain*
  as well as for a tower, so every wall lost its tile. The original code dodged this with a separate
  branch for `Blocked`; the refactor merged the branches and inherited the bug.
- **Inactive brush swatches went grey**, dimmed with alpha so the slate ramp behind them blended
  through. Darkened instead of faded — a swatch must never show a hue the theme does not have.
- **The placeholder bush was one flat green square**, authored within ~14 levels of its own ground.
  The same failure, and the same fix, as the original slate terrain ramp. Now written into the tile
  README as a rule rather than left as an anecdote.

## Scope, and what stayed out

Recorded in the editor spec. Still out, deliberately:

| Not in | Why |
|---|---|
| Per-cell tile placement | Choosing *this* bush for *that* cell needs a new per-cell layer in the map format. A format change, not an extension. |
| Tile authoring in-editor | The editor selects tiles. It does not draw them. |
| Terrain height, decoration | Unchanged from the v1 exclusion. |
| Wave editing | Unchanged. Still out by decision. |

## Player-Facing Change

None yet — no shipped map names a tile theme. `crossroads` stays `slate`, `gauntlet` stays
`mountain`. This is a pipeline, and the art that will use it does not exist.

## Known Not Verified

- **Mouse pass-through under the brush bar.** `MouseFilter.Ignore` is set on every control, but the
  capture harness cannot click. First thing for a human to try.
- The layout at window sizes other than 1280×720.
- `F7` picking up a folder created *while the editor is running* — same `Scan` as startup, but the
  act itself was not performed.
- Whether the placeholder tiles look good. They are placeholders; the bar is readability.
